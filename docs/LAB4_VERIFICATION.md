# Отчёт о реализации и проверке ЛР №4

Проверка выполнена 2 ноября 2026 года в Windows, .NET SDK 10.0.400,
runtime 10.0.11, PostgreSQL 17.6. Git commit и staging не выполнялись.

## Что реализовано

- PostgreSQL persistence на Npgsql 10.0.0 без ORM; четыре таблицы, FK, PK и CHECK.
- Новый семестр, явное продолжение по UUID, список незавершённых сессий.
- Транзакционная запись дня, обработанных занятий, прогресса и RNG.
- Полная загрузка истории и исходных правил без повторного вызова фабрики.
- Восстановление стратегии по истории и сохранённой конфигурации.
- SplitMix64 v1 с явным состоянием; отдельная случайность генерации правил.
- Неполные дни вылета, запрет продолжения вылетевших и завершённых сессий.
- Пятисекундный интервал, остановка клавишей и Ctrl+C, вывод после COMMIT.
- Проверка ожидаемого номера дня и блокировка строки от конкурирующей записи.
- Настоящие PostgreSQL-тесты, Compose и учебная документация.

## Схема и восстановление

`semesters` — корень сессии. `semester_teachers` и `simulation_days`
ссылаются на её UUID. `lesson_results` ссылается на составной ключ дня
и на составной ключ преподавателя. PK занятия запрещает повтор предмета
за один день одного UUID.

Сохраняются UUID, UTC-время, статус, следующий день, накопленное удовольствие,
вылет, состояние/версия RNG, период наблюдения, порог риска, порядок преподавателей,
их фактические правила и зависимости, все проведённые дни и занятия.

История восстанавливается в порядке номеров дней. На первом решении новая
стратегия последовательно обрабатывает полную историю с прежними ограничениями
видимости; это восстанавливает веса и `_processedDays`. Новый RNG получает
сохранённые 64 бита состояния. Фабрика преподавателей при загрузке не вызывается.
Первый проведённый день равен `next_day`; повторная запись старого дня отвергается.
Равенство непрерывному прогону проверено по каждому занятию, включая оба исхода
`Check50`, на трёх границах сохранения вокруг периода обучения.

Docker на машине проверки отсутствует. Использованы существующие исполняемые
файлы PostgreSQL из `D:/PostgresSQL/16/bin` (фактическая версия сервера — 17.6)
для **отдельного** временного кластера:

```text
Каталог: %TEMP%/csharp-lab4-postgres
Адрес:   127.0.0.1:55434
Базы:    lab4_tests, lab4_smoke
Роль:    lab4_test
```

Тестовое подключение не содержит пароля: временный кластер создан с trust
и доступен только через loopback. Это конфигурация проверки, не рекомендация
для пользовательского сервера. Каждая fixture дополнительно создаёт и удаляет
только собственную схему с непредсказуемым именем. Существующая служба PostgreSQL,
её настройки и базы не изменялись.

Команда фактического тестового прогона:

```powershell
$env:LAB4_TEST_POSTGRES = 'Host=127.0.0.1;Port=55434;Database=lab4_tests;Username=lab4_test'
dotnet test Csharp.sln --no-build --no-restore
```

После проверки временный сервер остановлен; каталог с его данными оставлен.
При необходимости именно этот кластер можно снова запустить:

```powershell
& 'D:/PostgresSQL/16/bin/pg_ctl.exe' -D "$env:TEMP/csharp-lab4-postgres" -l "$env:TEMP/csharp-lab4-postgres/server.log" -o '-h 127.0.0.1 -p 55434' -w start
```

## Smoke-тест с настоящим перезапуском процесса

1. Новый процесс `Csharp.dll --new-semester` создал UUID
   `fe3360d8-e128-4b7d-9d33-470c4cabecb0` в отдельной базе `lab4_smoke`.
2. Остановка клавишей `q`: код выхода 0. SQL подтвердил `next_day = 5`,
   удовольствие 5, пять дней и по шесть занятий в каждом.
3. Новый процесс `Csharp.dll --resume-semester <тот же UUID>` объявил
   «следующий день: 5» и начал именно с дня 5. Повторной генерации правил не было.
4. После продолжения и Ctrl+C SQL показал `next_day = 39`, удовольствие 155,
   дни 0…38, 234 занятия и 234 уникальных ключа занятий.
   Все шесть строк правил/зависимостей совпали с результатом до перезапуска.
   Терминальный запуск после Ctrl+C вернул код 1, при этом сохранение осталось
   целостным и активным. Штатная остановка по клавише отдельно проверена с кодом 0.
5. `--list-semesters` показал этот UUID. Продолжение несуществующего UUID
   выдало «Семестр ... не найден» с кодом 1 и без создания новой сессии.

## Запуск и ограничения

Точные команды создания базы, Compose, конфигурации, нового семестра,
остановки, продолжения, тестов и SQL приведены в
[учебных заметках](LAB4_POSTGRES_STUDY_NOTES.md).

- Все требуемые сценарии реализованы и проверены на настоящей PostgreSQL.
- Compose добавлен, но не запускался: Docker отсутствует. Альтернатива
  с установленной PostgreSQL реально проверена.
- Без отдельной `LAB4_TEST_POSTGRES` интеграционные тесты явно пропускаются.
- Сохранение происходит между днями. При остановке внутри незакоммиченного дня
  этот день будет проведён заново из последнего сохранённого состояния.
- Схема создаётся воспроизводимым SQL, но автоматических миграций чужих схем нет.
- Для старых сохранений нельзя незаметно менять алгоритм RNG или обучения стратегии.

Использованная документация:
[Npgsql: параметры и транзакции](https://www.npgsql.org/doc/basic-usage.html),
[PostgreSQL: ограничения таблиц](https://www.postgresql.org/docs/17/ddl-constraints.html).
